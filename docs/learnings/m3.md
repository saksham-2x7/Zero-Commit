# M3 Learnings — Frontend (Janani)

## What I didn't know before

- **Server-time based countdowns**: I initially thought about using the browser clock for the countdown, but the spec explicitly says `expires_at - server_time`. Using the local clock would drift and cause confusing UX if the clocks are out of sync.

- **EventBridge Scheduler accuracy**: The mock simulates the auto-revert using `setTimeout`, but in production the scheduler fires with ~5s jitter (ASSUMPTION-1). The UI must gracefully handle this — when countdown hits 0, the status might still be PENDING for a few seconds before the scheduler fires.

- **Error code breadth**: The spec has 17+ distinct error codes. A good error map matters more than I expected — an on-call engineer under stress needs plain English, not `SG_NOT_MANAGED`.

- **Monkey-patching fetch for mocks**: The `VITE_MOCK=1` pattern works by overriding `window.fetch`. The trick is to preserve the real `fetch` for non-API calls (like loading `/config.json`). I initially broke config loading by not doing this.

## What I know now

- Dark themes aren't just aesthetic — they're genuinely easier to read for on-call dashboards where ambient light is low and attention is critical.

- The "planned delta" preview before submit is crucial UX. Seeing "REVOKE tcp:80→80 0.0.0.0/0" in a formatted preview prevents costly mistakes.

- CSS custom properties + system fonts = fast, bundled, zero-CDN UI. No Google Fonts needed.

- `sessionStorage` for the bearer token is the right trade-off: survives page refresh within the tab but doesn't persist across sessions or leak to other tabs.

- Polling at 1s with `setInterval` is fine for this use case (short-lived changes, single user). No need for WebSockets.
