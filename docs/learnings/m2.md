# Learnings (M2)

1. **DynamoDB Reserved Words**: `status` is a reserved word in DynamoDB ConditionExpressions. When using it in `UpdateItem` or conditions, you must map it via `ExpressionAttributeNames={"#st": "status"}` and use `#st = :P`.
2. **Moto Limitations**: The `moto` library lacks support for `EventBridge Scheduler` (`scheduler` boto3 client). To test the lambdas, we had to mock `get_scheduler_client` completely and rely on standard assertions for the DynamoDB state changes.
3. **Decimal Serialization**: Boto3 DynamoDB operations return numbers as `Decimal` objects. When returning these inside `json.dumps()`, a custom `JSONEncoder` (like `DecimalEncoder`) is necessary to prevent serialization errors.
4. **Conditional Update Rejections**: Catching `ConditionalCheckFailedException` is robust for ensuring that race conditions (e.g. late confirm vs scheduled revert) resolve exactly as the spec dictates, dropping the loser without locking.
