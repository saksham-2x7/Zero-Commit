# M2 Learnings — Core (Hamza)

- Before: I trusted unit tests on mocks to validate integration correctness; after: unit tests on mocks missed an env var name mismatch and a missing DynamoDB expression value that real AWS rejected.
- Before: I thought passing an error handler without explicit cleanup was fine; after: unhandled exceptions between T0 and T1b left DynamoDB items stuck in PENDING with security-group locks held until manual cleanup.
- Before: I assumed EventBridge Scheduler execution would strictly match the exact TTL; after: observed Scheduler one-time execution in ap-southeast-2 had ~30s lag beyond the 60s window.
- Before: I assumed stubbed error testing would automatically cover AWS parameter types; after: real botocore Stubbers are required to catch parameter validation mismatches and unused expression attribute values.
- Before: I treated revert as simple rollback; after: per-op reconciliation with fresh Describe calls is essential to avoid undoing rules Deadman never touched or failing on concurrent external mutations.
